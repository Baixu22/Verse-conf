# VerseConf 最终收尾裁决

日期：2026-09-28。状态：**独立产品线冻结，源码与研究证据保留**。

## 1. 决定与范围

现有实现具有工程价值，但没有证明真实宿主采用后的净收益。停止对独立语言、编辑协议和平台的持续投入，不要求先完成宿主并入才能结束项目。

| 范围 | 决定 |
| --- | --- |
| `.vcf`、`#@schema`、意图协议与 spec | 冻结；未实现的设计不是路线图 |
| CLI / MCP / 核心库 / TOML / JSON | 保留当前源码与回归；不承诺新版本、默认安全性或主动维护 |
| LSP / VSCode / wasm / 多平台分发 | 停止持续构建与扩张；保留历史实现 |
| Docker | 保留占位文件作为现状，不把它描述为可用镜像，不补建 |
| 发布 | 不再计划 crates / npm / VSIX / CDN 新产物；不撤销历史包 |
| 自动 CI | 停止 push / pull_request 触发；仅保留手动证据与 Rust 验证 |
| 模型实验 | 不启动第六轮；保留五轮原始数据、预登记、裁决和运行器 |
| 宿主并入 | 本次不实施；不修改 DSH / ZCode / 用户设置，不引入新的格式或依赖 |

不修改许可证、不删除历史源码、不重写实验数据。冻结前未提交的 JSON 适配、规则修复和实验材料一并保留，不将它们误称为已发布版本。

本次只在本地源码树落实收尾。没有提交、推送、设置 GitHub archived、撤包或修改远程仓库设置。远程 Actions 和页面只有在这些改动被提交并推送后才会采用新状态；既有远程分支保护要求未改动。

## 2. 能够成立的结论

### 编辑接口

[确认性预登记](../benchmark/confirmation/PREREGISTRATION.md)测 TOML 标量 set，不是 `.vcf` 语言或完整宿主。共 79 任务、16 来源、三臂各 474 次，合计 1422 次运行 / 调用尝试。失败保留在分母；重复运行不是独立样本。

| 臂 | 语义正确 | 严格字节保真 |
| --- | ---: | ---: |
| host-string-replace | 462/474 | 459/474 |
| toml-edit-span | 430/474 | 430/474 |
| verseconf-intent | 421/474 | 421/474 |

intent 的模型 token / 严格正确结果为约 3767.6，对照 span 约 3460.9，高约 8.9%，没有达到净收益目标。
提示对命名数组路径的介绍不完整、span 与 intent 对值的类型处理不同、语义读回复用被测实现，都限制因果解释。来源聚类区间也限制普遍优越性推断。

这不改变停止推广 intent 的投资判断：举证责任在新增接口，而不是要求对照证明它在所有场景都更好。

### 安全门禁

后续五轮是同 8 文档、12 任务上的规则与测量迭代，不是五个独立 holdout，也不是五次尝试证明新语言。
[第五轮历史裁决](../benchmark/gate-increment-round5/VERDICT.md)记录 72 次机会、60 次成功生成、12 次失败；按冻结结果谓词 A=9、B=4，拦截 5 次；5 次拒绝均被分类为政策拒绝。

它证明检查确实能拦截一部分候选。它没有证明：

- 拒绝之后模型仍能完成用户的原任务；
- 所谓安全替代写法被目标程序加载并产生预期效果；
- 人工修复、模型轮次、耗时或总成本减少；
- 在独立未见宿主上的误拒率和安全收益。

“存在真实上游配置”与“在真实宿主写路径中采用”是不同证据。库示例、MCP test-host 和临时 npm consumer 也不能代替持续使用。

## 3. 对历史结论的补充限制

历史文件原样保留。本节是收尾时的限定，不追溯改写原始裁决。

1. **显著性未落实。** 首轮要求来源聚类差异区间不跨 0，第五轮仍写“显著低于”；[运行器](../benchmark/gate-increment/run.mjs)的裁决只是 `B < A`，不能据此宣称通过该门槛。
2. **历史冻结不完整。** [冻结核验](../benchmark/gate-increment/verify.mjs)覆盖预登记、任务和文档，没有绑定运行器、分类器或被测二进制。当前 `--grounding` 汇总选择旧问法 `misrejects` 作预算计数，与第四轮归档使用事实核对假阳性的口径不同，不能承诺原样重算所有历史裁决。
3. **发生率分母有限定。** 第五轮 15% 是 9/60 成功生成，不是 9/72 全部机会。调用失败留在总记录中，但没有进入该发生率分母。
4. **零实现假阳性不是零用户成本。** 0/68 的 68 由确定性控制与无风险生成混合构成，并非 68 次独立误拒评审；即使套用 Rule of Three，3/68≈4.4%，也不足证明 ≤2%。
5. **形态分类器不是独立业务 oracle。** `SEC-005` 的形态核对不能确认字段真的控制 TLS；政策拒绝不进入实现假阳性预算，不代表拒绝成本消失。
6. **不追溯替换风险定义。** 新的 `--p2-aligned` 使用更接近被测实现的谓词，不能用它把第五轮冻结残留 4 改写为 0，或为旧轮次补造独立证据。

确认性字节判定源码存在潜在宽松点；收尾评估对全部 1310 个 `byte_ok` 输出另外按冻结目标值区间核对，没有发现与预期字节不一致。因此不将潜在判定漏洞描述为已经污染本批通过数字。

## 4. 安全边界与可复用部分

[known_boundaries.rs](../crates/verseconf-json/tests/known_boundaries.rs)记录冻结实现的典型边界：

- `verify_email=false` 被当作关闭 TLS 校验；规则只匹配路径中的 `ssl` / `verify` 子串。
- `NODE_TLS_REJECT_UNAUTHORIZED="0"` 未被该规则覆盖。
- 无 schema 时类型变化和删成 `{}` 可以通过；提供 schema 才有相应结构约束。
- 同规则、同位置的既有风险替换，未必增加差分实例计数。

稳定拒绝码、按实例比较新增发现、局部源码保真和正反成对测试可供参考；不建议照搬启发式安全政策。
原子替换不等于历史回滚；schema 不等于宿主加载；MCP 判定不等于不可绕过提交；CLI 的重读加 rename 不等于严格 CAS。

如果将来确有宿主需求，应复用其实际解析器、生效配置、schema 和提交入口。特别是 YAML 不是本项目当前支持的门禁格式；给某一个 settings provider 加检查，也不会自动覆盖通用文件编辑或 shell 写入。此处说明迁移边界，不建立移植任务或工期承诺。

- `benchmark/gate-increment*/`：五轮任务、文档、运行记录和历史裁决。
- `benchmark/analysis/`、`benchmark/ablation/`、原有保真基准：分析方法与机制实验。
- `crates/`：当前实现与回归，包括收尾前尚未提交 / 发布的工作。
- [冻结前入口快照](archive/2026-09-28/README.md)：原中英文 README 和两个 workflow 按字节保留为 `.txt`，以免旧流水线继续被识别执行。
- [closeout-snapshot.json](../benchmark/closeout-snapshot.json)：收尾时文件 SHA-256、原 Git HEAD 和时间语义。

快照覆盖 benchmark 的全部历史文件、当前源码及文档、原始入口快照，以及已存在的 confirmation 逐运行输出；不收录 `.git`、`target`、依赖目录、个人 `.cargo` 配置、凭据或模型连接设置。
它只是**收尾时的完整性记录**，不能证明历史实验使用了当前实现，更不能修复缺失的运行期二进制指纹。

[verify-closeout.mjs](../benchmark/verify-closeout.mjs)只读取文件、检查哈希并运行原来的 `--verify` 检查，不调用模型、不重写结果。新增证据应另建附录，不应为了检查通过而覆盖此快照。
