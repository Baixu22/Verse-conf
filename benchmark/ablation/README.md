# 消融实验：编辑机制 vs 编辑机制 + 校验层（TF-0079）

要回答「这个项目到底值不值得继续」，必须把**编辑机制**与**安全门禁**的贡献拆开：
前者只是格式保真，后者才是安全闭环。混在一起测，就分不清收益来自哪一边。

## 为什么另立一组任务

预登记（[`../confirmation/PREREGISTRATION.md`](../confirmation/PREREGISTRATION.md)）里的
79 个任务是**刻意门禁中立**的：两臂输出实测逐字节相同，所以那份实验**测不到校验层**。
这一点在 `confirmation/README.md` 里已经写明——「要评估校验层，得另立一组任务与另一份预登记」。

这份就是那一组。**它在开跑之前固定**：改了它就必须作废本轮数据重新跑。
任务集同时以数据形态快照在 [`tasks.json`](tasks.json)（由 `examples/ablation.rs` 生成）。

## 两臂

| 臂 | 校验层 | 说明 |
| --- | --- | --- |
| `mechanism-only` | 关 | `TomlGuard::edit_mechanism_only()`：复用 `toml_edit` 定位值区间、只替换目标字节 |
| `mechanism-plus-gate` | 开 | `TomlGuard::default()`：写入前做 schema 与安全双重校验 |

两臂的输入完全相同，唯一差别是写入前有没有校验层。

## 两组任务

- **`blocking`**：改动引入的是 **Critical / High** 实例（SEC-001 / SEC-005 / SEC-SENS-001）。
  门禁的契约是拒绝这类改动，所以对照臂会**静默**写入一个高危项，实验臂会拒绝。
- **`advisory`**：改动引入的是 **Medium / Low** 实例（SEC-002 / SEC-003 / SEC-004）。
  门禁按设计只告警、不阻断，所以两臂都放行。这是安全承诺的一条边界，必须如实报告。

## 度量口径

关键是**不信任门禁的自述**。改动有没有引入高危实例，由实验代码用 `high_risk_instances`
在改动前后各算一次、再取差集得出，而不是看门禁有没有报错。

| 指标 | 定义 |
| --- | --- |
| 静默写入高危实例 | 改动被应用、且改动后相对改动前新增了 Critical/High 实例——调用方拿不到任何信号 |
| 挡住真实引入 | 门禁拒绝、**且**独立复核确认这条改动确实会新增高危实例 |
| 误拒 | 门禁拒绝了本来应该放行的改动 |
| 等价安全写法 | 同一个意图存在被门禁接受的等价写法（否则拒绝就是死路） |

「拒绝次数多」本身**不算**安全收益——只有「拒绝确实挡住了一次真实引入」才算。

## 怎么跑

```bash
# 跑实验并写报告（不调用任何模型）
cargo run -p verseconf-toml --example ablation

# 不变量回归（在 cargo test --workspace 里，CI 阻塞）
cargo test -p verseconf-toml --test ablation
```

产物是 [`latest.md`](latest.md) 与 `latest.json`。两者都**不写时间戳**：
同一份代码重跑必须逐字节相同，否则「报告有没有被手改过」只能靠人眼看。

## 本轮结果

| 指标 | 只保留编辑机制 | 编辑机制 + 校验层 |
| --- | --- | --- |
| 静默写入高危实例的任务数 | 5 | **0** |
| 拒绝数 | — | 5 |
| 其中确实挡住了一次真实引入 | — | **5** |
| 拒绝信息指出具体实例 | — | 5 |
| 等价安全写法被接受 | — | 5/5 |
| 误拒（79 条预登记中立任务） | 0 | **0** |
| 告警级改动两臂都放行 | 3/3 | 3/3 |

读法：对照臂把 5 条会引入高危项的改动**全部静默写入**；加上校验层后这 5 条全部被拒绝，
且每一次拒绝都确实挡住了一次真实引入，不是「为了拒绝而拒绝」——同一条改动换成等价的
安全写法（例如把写死的口令换成 `${DB_PASSWORD}`）都会被接受，79 条中立任务也一条都没被误拒。

## 边界（不要在它之外引用）

- **只测编辑机制与安全门禁的贡献**，不测模型行为：本实验不调用任何模型。
- **门禁的契约只覆盖 Critical / High**：`advisory` 组的 3 条改动按设计只告警，两臂都放行。
  不能把「没有阻断」说成「没有引入风险」。
- **任务集是固定的 8 条，不是随机抽样**：覆盖全部 6 条规则码，但样本量小，只用于判断
  「校验层有没有可测的贡献」，不用于估计真实场景的误拒率。
- **误拒控制用的是刻意门禁中立的 79 条任务**：只能证明门禁不是在一律拒绝，
  不能证明它在真实高风险语料上的误拒率。
