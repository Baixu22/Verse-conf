# 确认性复验的预登记（TF-0071）

> 冻结物：`tasks.json`（任务集）、`weights.json`（加权分布）、`meta.json`（指纹）、
> 判定口径（本文件第四节）。生成器：`crates/verseconf-toml/examples/generate_tasks.rs`。
>
> 核验：`node benchmark/confirmation/preregistration.mjs --verify` +
> `cargo test -p verseconf-toml --test preregistration`

## 〇、这份文件要解决的问题

这个项目已经因为**研究者自由度**翻过两次结论：判定器在实验中途被加强过一次，
任务集也是在看到空结果之后扩大的。确认性复验的全部价值来自「在看到数据之前
就把规则写死」，所以这份文件在**开跑之前**把六件事定下来：语料、任务构成、
判定口径、重试规则、失败处理、统计方法。

**第一次运行之后，这份文件和它引用的冻结物都不再改动。**
要改就必须作废本轮已经产生的全部数据，重新预登记、从头再跑——没有例外，
因为「看到一半结果再调规则」正是要防的那件事。

## 一、语料

`benchmark/holdout/`，16 份文档 / 16 个来源簇 / LF 8 份 + CRLF 8 份，
语料指纹 `69b8d6df86be4eba4b89e40798333d6a9fe058df8d8a71f4e941f1552f7f6ac3`。
来源、排除规则与已知边界见 `benchmark/holdout/README.md`。

已用于探索性实验的 `codex` / `starship` / `rtk` 三份按规则排除。

## 二、任务构成

### 2.1 生成规则（写死，不看结果）

任务由解析器生成，不由人挑：手写任务集做不到 TF-0071 那条硬验收
——「任务必须真正命中它声称覆盖的特征，而不是『文件里含有该特征』」。

1. **候选** = 能用路径定位、值是**单行标量**的键值对。路径支持普通键，
   也支持 `[[key]]` 里按字段匹配的元素定位。
2. **特征顺序**：字符串 → 整数 → 布尔 → Unicode → 行尾注释 → 带引号的键路径 → 浮点。
   按这个顺序各挑一个尚未选中的候选，使这份文件能覆盖的特征都被覆盖。
3. 不足 4 个按文档顺序补齐，超过 6 个按上面的顺序截断。
4. 每个候选都实测过：应用后结果仍然合法，且**不引入新的高危实例**
   （否则安全门禁会拒掉它，任务就测不到编辑机制了）。

「Unicode」只在**原文值与替换值两边都是非 ASCII** 时才算命中：否则这条任务
做的是「把字形删掉」，而不是「在非 ASCII 上做替换」。

### 2.2 冻结事实

| 项 | 值 |
| --- | --- |
| 任务数 | **79** |
| 覆盖文档 | 16（每份 4–6 个） |
| 用 `[[key]]` 元素定位的任务 | 7 |
| 任务集指纹 | `f5b48836a2a27a2249dd25b565d791df8fff67c7de981d2055d0ff1f1d3a685d` |
| 生成器指纹 | `28a3e46eb501a5fca39c5e753a1ad2386e42de218f273540dc9cfffe7b2b92a7` |

判定口径与门槛写在本文件里，所以**本文件也是冻结物**：`meta.json` 记录它的
SHA-256，改一个字的门槛都会被 `--verify` 报出来。

特征覆盖：

| 特征 | 任务数 | 备注 |
| --- | --- | --- |
| 字符串 | 49 | |
| 布尔 | 16 | |
| 整数 | 12 | |
| 带引号的键路径 | 6 | |
| Unicode 字形 | 3 | opendal / regex / versepixpin |
| 浮点 | 2 | |
| **行尾注释** | **1** | 只有 pandas 一份文档有；CRLF 侧为 0 |

每一条任务的 `evidence` 字段写明它为什么声称覆盖某个特征，并由
`crates/verseconf-toml/tests/preregistration.rs` 逐条回查——多报一个特征
（把「文件里含有」冒充成「任务命中了」）会直接让测试失败。

### 2.3 本轮只覆盖标量 `set`

`insert` / `delete` 与复杂值（多行数组、内联表、多行字符串）**不在本轮任务集里**。
理由有两条：TF-0071 的验收写的是「标量 set 任务」；而且 TF-0078 的验收要求
复杂值的结论**分开报告**，不能与单标量混在一起。它们要另起一组任务与另一份预登记。

## 三、判定口径（两个主口径，分开报告）

判定器**不读被测实现的自述**，只看原文与结果两份文本。

**口径 B（语义正确）**：用适配层的 `expect` 把目标路径的值读回来，必须等于要求的值。

**口径 A（严格字节保真）**：在口径 B 之上再加七条字节检查：

| # | 检查 |
| --- | --- |
| 1 | 只允许**一段**连续差异 |
| 2 | 差异段不得含键名 |
| 3 | 差异段不得含 `=` |
| 4 | 行数不变 |
| 5 | 目标行等号右边的值正好是新值 |
| 6 | 目标行必须等于「原文该行、只把值换掉」——**行尾注释因此不能动** |
| 7 | 目标行等号左边原样 |

两个口径各自给通过率与区间，**不合成一个数**。两者之差就是「值改对了但格式被动了」。

判定器一旦冻结就不再改动。**若必须改，作废本轮并重新开始。**

## 四、重试规则

- 每个（任务 × 方案 × 模型档位）跑满预登记次数 **R = 3**。
- 每次运行**最多一次模型调用**，不做自动重试。
- 模型版本与推理设置固定并记录；档位按 TF-0072 的结果分层报告，不合并。
- 判定器只跑一次，不看结果调整。

## 五、失败处理

| 情形 | 处理 |
| --- | --- |
| 模型输出无法解析成编辑计划 | 记该次运行**语义失败** |
| 工具拒绝（`unsupported_target` / `target_not_found` / `security_rejected` …） | 记**语义失败**，并单独统计拒绝码分布 |
| 文件没有被改动 | 记**语义失败** |
| 模型调用本身失败（网络、超时、限流） | 记该次运行失败，**不重试**，计入分母 |
| 判定器自身出错 | 该次运行**作废并记录**，不得静默丢弃 |

**任何一次运行都计入分母。** 剔除失败运行是最容易把结论做漂亮的一步，
所以这里明确禁止。

## 六、统计方法与聚类方式

写死在 TF-0073 的实现里（`benchmark/analysis/cluster_report.mjs`）：

- **独立单元是来源簇**（16 个），不是运行、也不是文档。
  cluster bootstrap 重抽来源簇，簇里的文档、文档里的任务、任务里的重复运行整体跟着走。
- 重抽 **2000** 次，种子 **20260926**（结果逐字节可复现）。
- 按文档、行尾类型、模型档位、方案分别列表；只有 1 个来源的分组不给区间。
- 加权汇总用 `weights.json`（LF 0.9 / CRLF 0.1），且**不得**称为生产环境平均值：
  权重是假设，不是测量结果。语料是 8/8，与目标分布差 40%，报告会打出过采样警告。
- 每个通过任务的 token 作为成本代理；不同方案的 token 结构差异大，
  按不同费率加权后排序可能变化，所以成本结论必须附口径说明。

## 七、预登记门槛与裁决规则

### 7.1 门槛只有一个来源

门槛**不是**在本文件里新立的，而是直接取自全局目标 TF-0001 的 `success_metrics`，
逐字如下：

| # | TF-0001 原文 |
| --- | --- |
| 硬门禁 | 公平对照中成功率不低于对照实现，且未新增任何静默误改 |
| 主指标 | 每个最终正确任务的总成本（模型输出、重试、人工修复与审查之和）较最薄的成熟保真库封装改善约 20% |
| 替代指标 | 若主价值判定为安全而非成本，则替代指标为：真实高风险任务上的误改显著减少，且误拒可被恢复 |

**为什么必须这样**：如果实验设计者另立一套门槛，就等于在同一次实验里同时决定
「测什么」和「多少算过」——那正是预登记要消掉的研究者自由度。要改门槛，
先改 TF-0001 的 `success_metrics`，并且作废本轮已产生的数据。

### 7.2 对照实现是谁（先把名字定死）

| 角色 | 方案 | 说明 |
| --- | --- | --- |
| 被测 | `verseconf-intent` | 意图契约 + span 写入 + 校验层 |
| 宿主现状 | `host-string-replace` | 多数 agent 宿主实际的编辑方式 |
| **最薄的成熟保真库封装** | **`toml-edit-span`** | 同一个 `toml_edit`、同一套 `{path, value}` 协议、只替换目标字节 |

注意：`toml-edit-thin` 用的是同一个库，但它走「解析 → 序列化」写入，**在 CRLF 上丢字节**，
所以它不构成「保真库封装」，只是负面对照。主指标的对比基准是 `toml-edit-span`。

### 7.3 硬门禁（任一不过 → 按 7.6 收尾）

| 编号 | 内容 | 判定方式 |
| --- | --- | --- |
| **H1** | 成功率不退化 | 语义正确率与字节保真率的**点估计**都不低于 `host-string-replace` 与 `toml-edit-span` |
| **H2** | 未新增静默误改 | 静默误改次数不高于两个对照 |

**H1 的诚实条款**：点估计不低于就记为通过，但结论**必须同时给出按来源聚类的区间**。
如果区间宽到区分不开被测与对照，结论要写成「不可区分」，**不得**写成「通过」。
16 个来源的 cluster bootstrap 区间可能确实很宽（探索性数据上宽到 `[50%, 100%]`），
这是要如实报告的，不是要绕过去的。

### 7.4 主指标（决定要不要继续投入）

**M1**：每个最终正确任务的总成本，相对 `toml-edit-span` 改善 **≥ 20%**。

**成本口径必须写清楚**：TF-0001 定义的总成本 = 模型输出 + 重试 + 人工修复与审查。
本轮**只能测到前两项**（token 与模型调用次数），人工修复与审查无法测量。
因此：

- M1 只在可测子集上判定，结论**只能表述为「模型侧成本」**，不得表述为「总成本」；
- 若模型侧已经不达标，不得用「人工修复那部分没算」来推定总成本达标——
  那是把未测量的部分当成对自己有利的假设。

### 7.5 替代指标（本轮**无法评估**）

**A1**：真实高风险任务上的误改显著减少。
**A2**：误拒可被恢复（拒绝必须能防错或被恢复；**拒绝次数多本身不算安全收益**）。

A1 需要一组**能触发安全门禁**的任务，而本文件第二节冻结的 79 个任务是
**刻意门禁中立**的（生成阶段就排除了会引入新高危实例的候选）。
在门禁中立的任务上，带门禁与不带门禁两臂的输出**逐字节相同**（已实测 79/79），
所以本轮对校验层给出零信息。

**结论：替代指标在本轮无法评估。** 要评估它，必须先另立一组任务与另一份预登记。

### 7.6 裁决规则

| 情形 | 裁决 |
| --- | --- |
| 硬门禁不过（H1 或 H2） | **收尾为「小型可靠配置编辑库」**，停止扩大平台叙事 |
| 硬门禁全过 + M1 过 | 继续投入；下一步只投第二种格式与更广分发中的**一项** |
| 硬门禁全过 + M1 不过 + A1 成立 | 主价值判为安全；继续投入，但只投安全闭环那一侧 |
| 硬门禁全过 + M1 不过 + A1 无法评估 | **收尾**；并在结论里写明「若后续建立了能触发门禁的任务集并显示误改显著减少，可以重新裁决」 |

### 7.7 已知的不利先验（写下来，免得事后找理由）

探索性数据（只用于设计，不能当证据）显示：

- 在编辑机制相同的 9 个任务上，`verseconf-intent` 1,421 token vs `toml-edit-span` 1,317 token，
  **贵约 7.9%**，而正确率完全相同（都是 39/39、0 静默误改）。
- 也就是说 **M1 的先验是不通过**。

这不影响开跑，也不允许因此放宽门槛。它的作用是：如果 M1 真的不通过，
结论不能写成「意外」，因为**这是开跑之前就写下来的预期**。

### 7.8 方法约束（不是门槛，但结论必须满足）

- 所有对照比较**必须按来源聚类报告**（TF-0073），不得只给点估计。
- 必须报告优势是否集中在少数来源上；若集中在 1–2 个来源，结论必须写明这一点。
- 加权汇总只能按 `weights.json` 给，且不得称生产环境平均值。
- 任何一次运行都计入分母（见第五节）。


## 八、边界（不要在它之外引用）

- **只覆盖标量 `set`**：`insert` / `delete` 与复杂值不在本轮。
- **行尾注释只有 1 个任务**（pandas，LF）。这条特征上的任何结论都不具代表性；
  CRLF 侧为 0，所以「行尾注释在 CRLF 上是否保真」本轮**回答不了**。
- **Unicode 只有 3 个任务**，同理只能算覆盖，不能算代表性。
- **16 份文档来自同一台机器**：来源是 16 个不同上游项目，但不是随机抽样自
  真实世界的 TOML 分布。7 份是包清单，真实宿主的应用配置形态没有对应样本。
- **门槛是判断标准，不是测量结果**。它们决定要不要继续投入，本身不是证据；
  而且它们不是本文件新立的，直接取自 TF-0001 的 `success_metrics`（见 7.1）。
- **替代指标本轮无法评估**：需要一组能触发门禁的任务，而那组任务尚未建立（见 7.5）。
  所以本轮能给出的最强结论是「主指标是否通过」，不是「要不要继续投入」的完整答案。
